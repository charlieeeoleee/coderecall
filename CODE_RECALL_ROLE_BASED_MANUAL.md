# Code Recall Role-Based Manual

## Document Purpose

This manual is designed for three main groups of users in the Code Recall system:

- Users and guest users
- Admins, such as teachers or facilitators
- Super admins, such as developers or system managers

The goal of this manual is to explain how each role uses the system, what features are available, and how the learning and monitoring flow works from start to finish.

---

# Part I. User and Guest User Manual

## 1. Introduction for Learners

Code Recall is a gamified learning system that helps learners study Computer System Servicing topics through:

- pre-tests
- modules
- quiz levels
- post-tests
- wrong-answer review
- memory flashcards
- XP and level progression
- badges and certificates

The system is designed not only to measure performance, but also to improve long-term memory retention.

## 2. User Types

### 2.1 Guest User

A guest user can explore the system without creating a permanent account.

Guest users can:

- open the dashboard
- access subjects
- study modules
- answer quizzes
- gain temporary progress on the current device

Important notes for guest users:

- guest progress is temporary
- progress is stored only on the current device
- if the guest logs out without registering, progress may be lost

### 2.2 Registered User

A registered user can use all learner features with saved progress.

Registered users can:

- keep permanent progress
- track XP and level
- unlock certificates
- send messages through Contact Us
- receive replies from admins
- use review and flashcard retention tools over time

## 3. Main Learning Flow

Each subject follows this sequence:

1. Pre-Test
2. Modules
3. Quiz Levels
4. Post-Test
5. Certificate Unlock

This structure helps the learner:

- measure current knowledge first
- study guided content
- answer smaller grouped assessments
- complete a final subject test
- receive proof of completion

## 5. Pre-Test

The pre-test checks the learner’s knowledge before studying the lessons.

Purpose:

- identify existing knowledge
- show readiness before the learning flow

Important reminders:

- the pre-test is part of progress tracking
- it helps compare before-and-after learning performance
- it contributes to subject completion flow

## 6. Modules

Modules are the lesson content pages of the system.

Inside modules, learners can:

- read guided lessons
- view images and examples
- use the progress rail
- answer quick checks
- follow checkpoints

Modules are designed to support structured reading and guided progress instead of random browsing.

## 7. Quiz Levels

Quiz levels are smaller grouped quizzes inside a difficulty path.

Each level:

- presents a short set of questions
- awards XP based on first-correct answers only
- supports confidence-based memory tracking

Important quiz-level rule:

- the learner has up to 3 tries where the retry rule is applied
- after the final allowed failed try, the question may become available again the next day

## 8. Confidence-Based Answering

After choosing an answer, the learner also chooses a confidence level:

- Sure
- Somewhat Sure
- Guessing

This helps the system detect weak memory even when an answer is correct.

If the answer is:

- wrong
- correct but low confidence

then the item may enter memory-retention review.

## 9. Post-Test

The post-test checks what the learner knows after finishing the study flow.

Purpose:

- measure improvement after modules and quizzes
- support certificate unlock
- support learner analytics

The post-test is one of the final parts of subject completion.

## 10. Wrong-Answer Review

Wrong-answer review helps learners revisit questions they missed before.

This feature allows learners to:

- view missed questions
- see the review rationale
- reopen the original activity
- focus on weak areas without restarting everything

## 11. Memory Flashcards

Memory flashcards are used for retention practice.

Flashcards can appear when:

- the learner answers a question incorrectly
- the learner answers correctly but chooses:
  - Somewhat Sure
  - Guessing

Flashcard buttons:

- Need Again
- Hard Recall
- Easy Recall
- Open Source

Meaning of each:

- `Need Again` means the learner still does not remember it strongly
- `Hard Recall` means the learner remembered it, but with effort
- `Easy Recall` means the learner remembered it confidently
- `Open Source` sends the learner back to the original learning activity

## 12. Recovery Feedback

When the learner corrects questions that were previously missed, the result modal may show a recovery message.

Example:

`Recovery win: you fixed 3 previously missed questions`

This helps the learner see real improvement, not only final score.

## 13. XP and Level Rules

Code Recall uses anti-farming rules for XP.

Current XP principle:

- XP is only awarded when a question becomes correct for the first time

This means:

- first correct answer gives XP
- wrong first, then correct later gives XP when corrected
- replaying an already-correct question gives no extra XP

This keeps the system fair and prevents easy XP farming.

## 17. Troubleshooting for Learners

### Flashcards appear often

Possible reasons:

- repeated wrong answers
- low-confidence correct answers
- short retention schedule settings

### XP does not increase after replaying

This is expected when the learner already answered those questions correctly before.

### Certificate is still locked

Check whether all required subject stages are completed:

- pre-test
- modules
- quiz path
- post-test

### Guest progress is gone

Guest mode is temporary. Registering is recommended if the learner wants permanent saved progress.

# Part II. Admin Manual (Teachers / Facilitators)

## 18. Admin Role Overview

Admins are responsible for:

- monitoring learner progress
- reading concerns and feedback
- replying to user messages
- checking weak areas and retention load

Admins do not only monitor scores. They also monitor whether learners are remembering content over time.

## 19. Admin Dashboard

The admin dashboard provides summary visibility into learner performance.

It can include:

- average pre-test score
- average post-test score
- completion rates per subject
- most-missed topics
- learner tables
- retention indicators

## 20. Learner Analytics

Admins can inspect individual learners and view:

- activity history
- weak topics
- subject status
- assessment performance bars
- retention snapshot
- due memory queue

This makes it easier to identify:

- learners who are progressing
- learners who are struggling
- learners who need intervention

## 21. Retention Analytics

Admins can track retention-related indicators such as:

- due memory cards
- learners with due cards
- low-confidence cards
- retention recoveries
- highest due flashcard load
- lowest retention recovery

These metrics help determine whether learners are retaining knowledge and using review tools properly.

## 22. Contact Inbox

Admins can review learner messages in the contact area.

They can:

- view learner concerns
- read learner conversation threads
- reply to messages
- monitor support requests related to learning and system issues

**Suggested image to insert here**
- Screenshot of admin contact inbox

## 23. Suggested Admin Routine

A suggested daily or weekly admin routine may be:

1. Review Contact Us inbox
2. Check most-missed topics
3. Check completion rates
4. Review due memory-card load
5. Open learner profiles with weak progress
6. Reply to learner concerns

## 24. Troubleshooting for Admins

### A learner says they earned no XP

Check whether:

- the learner already answered those questions correctly before
- the XP anti-farming rule is doing its job

### A learner says flashcards appear too often

Check:

- confidence answers used
- frequency of wrong answers
- retention schedule settings

### A learner cannot send contact messages

Check:

- Firestore rules
- authenticated status
- role-based page access

# Part III. Super Admin Manual (Developers / System Managers)

## 25. Super Admin Role Overview

Super admins have broader authority than admins.

They are responsible for:

- system oversight
- developer-level review of learner trends
- contact workflow supervision
- retention and performance monitoring
- validating that the platform is functioning correctly

## 26. Super Admin Dashboard

The super admin dashboard is used to monitor system-wide health and performance.

It may include:

- all admin-level metrics
- broader retention oversight
- high-risk learner identification
- contact support visibility
- recovery trends

**Suggested image to insert here**
- Screenshot of super admin dashboard

## 27. Retention Oversight

Super admins should monitor:

- whether retention queue behavior is too aggressive or too weak
- whether flashcard recovery is actually happening
- whether low-confidence answers are becoming retention cards properly
- whether due-card counts are becoming unmanageable

This is important because retention is one of the core educational strengths of the platform.

## 28. System Configuration Review

Super admins and developers should be aware of:

- retention schedule controls in Settings
- XP anti-farming rules
- certificate unlock conditions
- role-based navigation
- contact visibility rules

## 29. Developer Checks

Recommended developer or super admin checks:

1. Verify quiz flows after code updates
2. Verify certificate generation after subject completion
3. Verify flashcard creation after wrong and low-confidence answers
4. Verify admin and super admin analytics after database updates
5. Verify private conversation history remains private

## 30. Developer Troubleshooting Notes

### If dashboard data looks delayed

Check:

- Firestore writes
- local cache values
- merge behavior between local and remote state

### If flashcards do not appear correctly

Check:

- retention queue payload
- confidence capture
- source question metadata
- image hydration fallback for image-based questions

### If certificates are incorrect

Check:

- completion flags
- result records
- certificate ID generation
- dual-completion condition logic
